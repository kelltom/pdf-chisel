# Phase 4.1: Developer Experience README - Context

**Gathered:** 2026-02-24
**Status:** Ready for planning

<domain>
## Phase Boundary

Add a README.md to the repository root that documents exactly how to configure a development environment, clone the repo, and run PDF Chisel locally on Windows. This covers dev setup documentation only — contributing guidelines, CI/CD, and distribution are out of scope.

</domain>

<decisions>
## Implementation Decisions

### Audience & tone
- Target reader: developer comfortable with a terminal, may not know Node/npm or Electron specifically
- Tone: purely technical, minimal — no explanations or fluff; commands and facts only
- Brief project description (1-2 sentences) at the top, then straight into setup

### Environment scope
- Windows only — no macOS or Linux instructions
- Node installation: recommend nvm-windows, specify exact Node version to install
- Prerequisites: Node (via nvm-windows) and Git only — no editor or extension requirements
- No environment variables needed for dev mode — omit any secrets/env var section

### Section coverage
- Sections to include: Prerequisites, Clone & install, Run in dev mode, Build for production
- No troubleshooting section
- npm scripts listed as commands only — no descriptions per command
- No project structure section

### Known gotchas — inline warnings only
- Node version mismatch: inline warning near the nvm-windows step that using the wrong Node version can cause Electron rebuild issues
- Windows antivirus false positives: inline note that unsigned Electron dev builds may trigger Windows Defender

### Claude's Discretion
- Exact markdown formatting (headers, code blocks, callout style)
- Which specific Node LTS version to pin (check current electron-vite/Electron 34 requirements)
- Whether to use GitHub-flavored `> [!NOTE]` callouts or plain markdown for inline warnings

</decisions>

<specifics>
## Specific Ideas

- "A good README should instruct which version of Node to install, and that is good enough" — don't over-explain Node/npm, just give the right version
- Electron knowledge should not be assumed — don't reference Electron internals in the README prose

</specifics>
