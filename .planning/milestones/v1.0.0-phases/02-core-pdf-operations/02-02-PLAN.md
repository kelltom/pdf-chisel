**File 1: src/renderer/src/lib/utils/page-range.ts**

Implement `parsePageRange` exactly as specified in the research document:
- Converts "1-5, 8, 12-15" → 0-indexed, deduplicated, sorted number array
- Empty input → returns all pages (0 to totalPages-1)
- Numbers beyond totalPages are silently clamped (excluded)
- Handles both range segments (`n-m`) and single page numbers

```typescript
export function parsePageRange(input: string, totalPages: number): number[] {
  if (!input.trim()) {
    return Array.from({ length: totalPages }, (_, i) => i)
  }
  const indices = new Set<number>()
  const segments = input.split(',')
  for (const seg of segments) {
    const trimmed = seg.trim()
    const rangeMatch = trimmed.match(/^(\d+)\s*-\s*(\d+)$/)
    if (rangeMatch) {
      const start = parseInt(rangeMatch[1], 10)
      const end = parseInt(rangeMatch[2], 10)
      for (let p = Math.min(start, end); p <= Math.max(start, end); p++) {
        const idx = p - 1
        if (idx >= 0 && idx < totalPages) indices.add(idx)
      }
    } else {
      const single = parseInt(trimmed, 10)
      if (!isNaN(single)) {
        const idx = single - 1
        if (idx >= 0 && idx < totalPages) indices.add(idx)
      }
    }
  }
  return [...indices].sort((a, b) => a - b)
}
```

Create `src/renderer/src/lib/components/OperationLayout.svelte`.

This is the shared structural wrapper that all three mode UIs (Extract, Split, Merge) will use. It enforces the locked UI consistency decision.

**Props:**
- `isProcessing: boolean` — controls spinner visibility and action button disabled state
- `result: OperationResult | null` — passed through to ResultsSummary
- `onReset: () => void` — passed through to ResultsSummary; clears all state

**Slots (Svelte 5 snippets):**
- `inputs` — mode-specific form fields (page range input for Extract, split controls for Split, file list for Merge)
- `actions` — the Execute button (labeled per mode: "Extract", "Split", "Merge")

**Layout structure:**
```
[inputs slot]         ← mode-specific controls
[actions slot]        ← Execute button (disabled when isProcessing)
[ProgressSpinner]     ← shown only when isProcessing=true
[ResultsSummary]      ← shown always (Reset button always visible)
```

The Execute button lives in the `actions` slot (owned by the mode component) so it can have the correct label. OperationLayout does NOT disable the Execute button itself — the mode component passes a disabled button in the `actions` slot when isProcessing is true (per locked decision: action button is disabled while processing).

Use Svelte 5 snippet syntax for slots (not the deprecated `<slot>` element):
```svelte
<script lang="ts">
  import ProgressSpinner from './ProgressSpinner.svelte'
  import ResultsSummary from './ResultsSummary.svelte'

  interface OperationResult {
    outputFiles?: string[]
    outputFolder?: string
    error?: { cause: string; fix: string }
  }

  let {
    isProcessing = false,
    result = null,
    onReset,
    inputs,
    actions
  }: {
    isProcessing?: boolean
    result?: OperationResult | null
    onReset: () => void
    inputs?: import('svelte').Snippet
    actions?: import('svelte').Snippet
  } = $props()
</script>

<div class="operation-layout">
  <div class="inputs-area">
    {@render inputs?.()}
  </div>
  <div class="actions-area">
    {@render actions?.()}
  </div>
  {#if isProcessing}
    <div class="progress-area">
      <ProgressSpinner />
      <span class="processing-label">Processing...</span>
    </div>
  {/if}
  <div class="results-area">
    <ResultsSummary {result} {onReset} />
  </div>
</div>
```

Add CSS using Catppuccin Mocha variables from app.css. Keep layout vertical (column flex), reasonable spacing between areas. Claude's discretion on exact pixel values — match the overall app aesthetic.
